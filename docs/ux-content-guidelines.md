# UX Content Guidelines

SSOT for ClassScout client-facing UI copy and product explanation patterns.

## Purpose

These guidelines keep the website understandable for first-time families and clear for provider or partner visitors without turning the UI into a long-form marketing surface.

## Core rules

- explain the product in plain language before adding flourish
- prefer one strong sentence over stacked supporting copy
- every empty state must tell the user what to do next
- trust language must be specific, short, and practical
- provider/business CTAs must explain the action, not just name it

## Homepage

Homepage copy must answer three questions quickly:

1. what is ClassScout
2. what can I browse here
3. what should I do next

Required homepage tone:

- local
- curated
- practical
- family-oriented

Avoid:

- generic marketplace language
- vague “discover more” phrasing without context
- stacked taglines that repeat the same idea

## Discover surfaces

Discover-page support copy should help the user browse, not narrate the whole product.

Required guidance:

- what the current page contains
- how to refine results
- whether the state is shareable or location-specific

Avoid:

- repeated headings that say the same thing
- long explanatory blocks above results
- filter labels that require internal vocabulary to understand

## Trust language

Trust copy should make the curation model understandable without exposing internal workflow detail.

Preferred themes:

- curated
- source-backed
- local relevance
- family usefulness

Preferred examples:

- `Curated local classes, camps, parties, and meet-ups across NYC.`
- `Source-backed family finds for New York City neighborhoods.`

Avoid:

- claims that imply real-time completeness
- references to internal AI/pipeline machinery in user-facing copy
- abstract quality claims with no concrete meaning

## Empty states

Every empty state must include:

- what happened
- why it may have happened
- the best next action

Required branches:

- no results because filters are too narrow
- no upcoming events in the selected window
- data failed to load
- content is not yet available for this location

Avoid:

- dead-end messages
- blaming technical systems the user cannot act on
- generic “Nothing found” copy

## Provider and partner CTAs

Provider-facing CTAs must be explicit about intent.

Use:

- `List your program`
- `Get in touch about a featured listing`
- `Tell us about your classes or camps`

Support line should clarify outcome:

- who the CTA is for
- what happens next

Avoid:

- vague `Learn more`
- sales language without operational meaning

## Writing constraints

- headlines: short and concrete
- support copy: usually 1 to 2 sentences max
- CTA labels: explicit and action-led
- labels: use plain language before internal taxonomy

## Review checklist

Before shipping client-facing copy changes, confirm:

- a first-time parent can understand the page quickly
- the copy still fits the thin-viewer product model
- trust claims are supportable
- empty states suggest a useful next step
- provider CTAs are explicit
